# Module Livreurs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the shop owner record her external couriers, hand them orders, run the end-of-day "point" (delivered / not delivered, cash, fees) and always know each courier's balance.

**Architecture:** Three services carry the rules — `ShippingZones` (zone + courier fee for a city), `CourierDispatch` (hand over / withdraw orders), `CourierSettlement` (point and payments, writing immutable `courier_movements`). Thin admin controllers and Inertia pages sit on top; the courier balance is always the sum of movements.

**Tech Stack:** Laravel 12, Inertia + Vue 3, Tailwind, MySQL (tests run on MySQL `chamse_testing`).

**Spec:** `docs/superpowers/specs/2026-11-04-livreurs-design.md`

## Global Constraints

- Branch: `feature/livreurs`, stacked on `feature/suivi-commandes` (PR #7). Merge order on GitHub: #4 → #5 → #7 → this one.
- Never send e-mails or customer notifications from dispatch, point or payment (same rule as `OrderController::bulkUpdateStatus`).
- An order is with at most one courier; it can be handed over only from `confirmed` or `processing`.
- Courier fee comes from the order's zone at hand-over time, is editable during the point, and is due for every order presented at the point, delivered or not.
- Amount to collect for an order = its `total` if `payment_status !== 'paid'`, else `0`.
- A validated point is never edited; corrections are new movements.
- UI: design system of `CLAUDE.md` (44 px touch targets on the point screen, amounts with `number_format($x, 0, ',', ' ') . ' F CFA'`), no Vue file over 500 lines.
- After any Vue change: `npm run build`, commit `public/build` in a separate `build:` commit.
- Known failing tests to ignore: 11 in `OrderCreationTest`, `ProductStockTest`, `ThermalPrinterTest`.

## Review Focus

1. Same point submitted twice (double tap, network retry) → second submission rejected, no duplicate movement, orders not re-paid. (Task 5)
2. Courier deactivated while he still carries orders → his point page still opens and the point can be settled. (Task 5)
3. Zone fee changed in settings after hand-over → order keeps the fee copied at hand-over. (Task 4)
4. Order soft-deleted while en route → not listed in the point, not counted. (Task 5)
5. Negative or non-numeric amount received / fee → validation error, nothing written. (Task 5)

**Interfaces:**
- Consumes: `Courier`, `CourierMovement` (Task 1), orders handed over by Task 4.
- Produces:
  - `CourierSettlement::preview(Courier $courier): array` → `[['order_id', 'order_number', 'customer', 'phone', 'city', 'to_collect' => float, 'fee' => ?float]]` for non-deleted orders `delivery_in_progress` with this courier.
  - `CourierSettlement::settle(Courier $courier, array $outcomes, float $amountReceived, ?string $note, ?int $userId): CourierMovement` with `$outcomes = [orderId => ['outcome' => 'delivered'|'failed', 'issue' => ?string, 'fee' => ?float]]`; issues allowed: `absent, injoignable, refus, reportee, autre` (required when failed). Throws `ValidationException` if an order is not currently en route with this courier.
  - `CourierSettlement::recordPayment(Courier $courier, float $amount, ?string $note, ?int $userId): CourierMovement` (`type` payment, `balance_change = -amount`).
  - `CourierSettlement::summaryText(Courier $courier): string` — WhatsApp text: one line per order en route `#{order_number} – {name} – {phone} – {city} – à encaisser {amount} F CFA`, then the total.
  - Routes: `admin.couriers.show` (GET `couriers/{courier}`), `admin.couriers.settle` (POST `couriers/{courier}/settle`, body `outcomes[orderId][outcome|issue|fee]`, `amount_received`, `note`), `admin.couriers.payments.store` (POST `couriers/{courier}/payments`, `amount`, `note`). Show props: `courier`, `orders` (preview), `balance`, `movements` (latest 30 with orders), `whatsapp_url` (`https://wa.me/<digits>?text=<summary>` or null without phone).
- Rules (spec): collected = Σ `to_collect` of delivered; fees = Σ fee (override, else order `courier_fee`, else 0) of **all** presented orders; `balance_change = collected − fees − amount_received`. Delivered → `delivered`, `delivered_at`, `payment_status` paid + `paid_at` if unpaid, courier kept. Failed → `processing`, courier/dispatch/fee cleared, `delivery_attempts + 1`, `last_delivery_issue`. Orders not in `$outcomes` stay en route. One DB transaction. No mail.
